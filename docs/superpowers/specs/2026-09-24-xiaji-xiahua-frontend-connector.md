# DramaClaw 虾塘完整前端移植与虾画连接器

范围说明：本文仍是“虾塘完整移植与基础素材连接器”的详细规格；其中关于 `/xiaji` 虾塘页面和本地资产发送/选择器的部分继续作为实现记录。虾镜整集/Beat 上下文投影采用[2026-09-25 独立规格](2026-09-25-xiaji-beat-context-canvas-import.md)，本文的基础素材导入不代表该功能已实现。当前只含虾料、虾塘、虾镜与原生虾画，不含虾面、回主线或视频生成。

状态：执行规格。此前“通用本地素材工作台即可”的 v19 范围已被本规格取代，不能作为完成依据。

## 1. 目标与成功标准

将 DramaClaw「虾塘」真实前端的页面结构、四类资产控件和本地可实现行为，完整复用/移植到 Infinite Canvas 的 `/xiaji` 独立全页。虾画继续使用 Infinite Canvas 原生画布。虾塘全页有“发送到虾画”，画布内有“虾塘素材”选择器；两个入口共用一个单向连接器，将所选虾塘记录及用户选择的关联媒体映射为画布已有节点并调用现有画布保存。

验收必须同时满足：

1. `/xiaji` 显示虾塘真实四类资产（角色、场景、道具、声线）及对应信息层级、筛选、详情、编辑器、媒体控件、确认框、预览、加载/错误/空状态和窄屏布局；不能继续以 `LocalAssetWorkbench` 或通用 `DomainAssetManager` 作为虾塘页面。
2. 来源控件逐项映射至 Infinite Canvas 页面与真实本地行为；涉及上游生成/项目任务/3D 服务的入口保留其页面位置和语义，标为当前不可用及原因，不伪造调用或结果。
3. 领域记录和关联媒体保存在 Infinite Canvas 现有素材 store，并通过现有媒体上传/持久化能力保存；角色、身份、变体、道具和声线字段通过现有 `Asset.metadata` 保存。
4. 虾塘发送与画布内选择器调用同一连接器；新增节点不覆盖已有节点/边，不自动生成边或媒体。重复、媒体缺失、上传部分失败和画布保存失败均有逐项结果。
5. 新建与已有画布的导入在浏览器中完成，刷新后仍存在；页面检查、测试和截图如实分开记录。

## 2. 明确不做的事

- 不运行、部署或连接 DramaClaw，不访问其 Host、API、数据库、任务或生成服务；不配置/要求 `DRAMACLAW_BASE_URL`、`DRAMACLAW_API_TOKEN`。
- 不移植 DramaClaw 后端，不新增 Go 路由、数据库、任务、生成、远端写回或 DramaClaw API 适配。
- 不把虾塘改成画布侧栏、项目/集数/分镜工作流页、通用素材页或简化目录页。
- 不因本功能范围清理、覆盖、重置其他已有脏改动；不改 DramaClaw 快照源码，不提交。

## 5. 本地领域数据与交互契约

沿用现有 `Asset` store，不新增后端 schema/API。身份、场景变体、声线槽位及项目旁白采用**独立、稳定 ID 的 text Asset 子记录**，不嵌套在父记录数组里；每条虾塘记录在 `metadata.xiaTang` 中保存 `schemaVersion: 1`、`domain`、`recordType`、`fields`，子记录另存 `parentId`。主实体使用 `recordType: "entity"`；角色身份使用 `identity`；场景变体使用 `variant`；角色或旁白槽位使用 `voice-slot`。头像、身份图、服装图、场景 master/reverse/pano/空间布局、道具参考图、声线音频仍各自是正常图片/视频/音频 Asset，以 `recordType: "media"`、稳定 `parentId`、`slot` 和可选 `versionOf` 标记关系。`Asset.id` 是唯一关系键；道具所属角色写入其 fields 的 `characterId`。

删除实体时先确认影响，删除该实体的 text 子记录，并解除媒体上的虾塘父子标记；媒体文件作为本地素材保留，避免误删被其他记录或画布引用的文件。用户单独删除媒体才调用现有 `removeAsset` 引用保护。修改元数据必须保留未知 metadata、未知 xiaTang 扩展字段和未编辑领域字段。通用素材不自动猜成虾塘记录。

本地页面只依赖 `useAssetStore` 与 Infinite Canvas 现有媒体/保存能力。若 store 仍在水合则显示加载；只有水合完成后才显示空态。添加、编辑、删除、媒体操作完成/失败应反馈真实结果；删除带关联资产时必须给确认和明确影响，不能删掉被其他画布引用的媒体。

连接器输入为用户明确勾选的虾塘记录与关联媒体 ID、目标画布，以及调用时读取的最新画布状态；全页和画布内选择器用相同映射函数。默认只导入所选记录，不因选中角色/场景而静默扩展所有媒体；详情里的媒体选择控件让用户逐项勾选。节点携带素材 ID、类别、标签、`metadata.xiaTang` 和 `parentId`/`slot` 关系字段。图片/视频/音频仍引用同一个本地 Asset 的 media URL/storage key，不复制上传、不自动生成节点边。输出逐项列出新增、重复跳过、缺失/不支持、上传失败和保存失败。

保存时从 Canvas store 的最新项目快照开始追加节点，原节点与 `connections` 原样保留；现有 `saveProjectAndWait` 是更新内存后再等本地工作区持久化，失败会抛错并设置 `localWorkspaceError`，不会声称已持久化。失败时连接器保留错误与重试所需的选择状态，不用旧快照回滚或覆盖用户在此期间的编辑。成功只在持久化 Promise 完成后报告。已有画布通过选择目标菜单选择；新画布先建项目后导入，同一弹窗支持两条路径。

## 6. 实施边界与风险

- UI 范围从上游真实组件/行为导出，优先迁移纯呈现层并替换数据控制器；禁止把 `drama-import.ts`、Drama hooks、remote query、任务 hooks 等放进 `/xiaji` 可执行依赖图。
- 完整迁移 UI 不等于接上其后端：不可用能力应保留入口位置和必要配置项布局，但标注当前目标应用本地没有相应能力并禁用。
- 两个项目根许可证不同（目标 AGPL-3.0、来源 Elastic-2.0）。保留来源许可与修改通知，逐文件清点被复制/改编内容和分发边界；不擅自把 Elastic 文件宣称为 AGPL。此法律/发行判断属于待确认风险，不隐去。
- 现有工作区有大量来自之前任务的改动，包含与本功能无关的后端 Drama 文件；本次不重置、覆盖、清理这些改动，也不通过它们实现虾塘。

## 7. 工作流门禁

1. Superpowers brainstorming：将本任务判定为对真实既有产品页的复用/迁移，目标为“在 Infinite Canvas 中以本地数据完整复现虾塘四类资产 UI，并可导入画布”，约束为不接源端服务；成功标准见 §1。

3. `architecture-analysis`、`api-and-interface-design`、`architecture-patterns`：固定领域记录、媒体引用、父子关系、页面控制器与单向 Canvas connector 的边界，不新造远端 API。
4. 实现前由独立 `architecture-critic` 审阅规格、计划、状态模型、license 隔离、数据流和测试范围；按 `frontend-design` 对来源手册截图和 DramaClaw 页面逐项检查视觉差异。首次复核确定了独立稳定子记录、删除仅解除关系而保留媒体、最新画布快照追加以及持久化失败不虚报成功；已写入本节和计划。
5. TDD：先对领域元数据、CRUD、关系/上传、连接器和关键 UI 行为写失败测试并保留 RED 证据，再实现 GREEN，最后 REFACTOR。每类行为分别报告验证结果。
6. 保护 dirty worktree，不提交。真实浏览器核对截图、两种导入路径、刷新持久化与 Network。工具无法读取 Network 面板时明确限制，不将源码搜索说成 Network 验证。
