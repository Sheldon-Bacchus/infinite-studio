# 连接组件审阅与补修

本轮以交接目录 connection-sdd 的修订稿为需求依据；仓库 specs/002-canvas-connection 仍是旧稿，任务不得据执行者自报勾选。仅拥有 Canvas Agent 与网页连接相关文件，不修改 workspace-service/main.go 或作品模块，不移植另一仓库，不运行测试、构建、服务或浏览器。

## 已确认的问题

- MCP sessionId 与绑定码按进程生成，共享进程中的聊天使用同一身份，不能证明聊天隔离。T004 没有真实桌面探针证据。
- HTTP 工具入口接受请求体 internal=true，能够跳过外部绑定验证。
- 回执 revision 仅检查非空；同连接内旧快照回执可以覆盖新同步状态。
- SSE 断开把执行请求设为 unknown，reject 回调又将其改为 failed。
- 强制接管在目标校验成功前修改旧租约；同通道重绑未取消旧待确认请求。
- 画布切换未永久撤销绑定，切回原项目可能恢复旧授权。
- 并发请求共用单个执行状态，先结束的请求可能提前解除其他执行请求的保护。
- 服务探测成功也返回非空文本，页面用 !detail 判定可达，导致错误状态。
- 接管 UI 仅看所选通道，没有按目标画布的占用者判断。

## 身份修正方案

采用显式凭据通道，放弃未经证明的 threadId 推断。目标聊天首次调用 canvas_connection_status（不带凭据）创建一个独立通道，返回绑定码和随机 channelToken；该聊天必须保留 token，并在之后所有工具调用、绑定与状态查询中显式携带。共享 MCP 进程不得缓存并自动套用“最近通道”。未携带、错误或被撤销的凭据拒绝读取与写入。

服务端只在创建响应中返回该通道 token；网页通道清单及普通状态、日志和 SSE 不返回 token。绑定码用于用户确认目标，不能作为调用凭据。通道名只作为可辨识标签，不能证明聊天身份。此为持有凭据的隔离，不承诺识别平台真实 threadId。

网页内 Agent 继续使用其 turn 固定网页路径，但 internal 布尔值不能作为凭据。HTTP 主进程创建仅内存存在的随机内部密钥，通过启动配置的环境变量传给自己的 MCP 子进程；HTTP 入口验证专用请求头后才允许内部路径。普通网页配置、健康信息和通道清单不包含该密钥。服务重启后旧凭据及绑定失效，必须重新创建并绑定。

## 验收与限制

主模型审阅所有修改与调用路径。静态检查应确认 A/B 即使共用 MCP 进程仍必须携带各自 token，B 接管后 A 读写拒绝，缺少 token 不回退焦点，internal=true 不能绕过，切换画布永久失效，unknown 必须显式强制接管。同通道重绑、并发执行及晚到结果按绑定 revision 校验。

同步成功须 clientId/projectId/revision 与本次提交三项一致，并按连接与快照代次拒绝旧回执。历史分页中间失败与重复游标必须显式失败。

真实桌面共享进程探针、浏览器 A/B×甲/乙、启动脚本和实际进程对齐仍无本轮运行证据。T011 移植保留用户确认门槛。不得把静态审阅或 AGY 自报描述为人工验收通过。
