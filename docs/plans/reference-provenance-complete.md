# 最终提示词与素材来源完整方案

用户要求直接修复后核对。此方案补充upstream移植，不能仅凭引用栏实现宣称完成。

## 数据与语义

- 当前引用由统一reference plan产生，正文标签与下方清单使用同一参与集合和提交顺序。候选与实际提交区分，不把未采用素材伪装成输入。
- NodeID是入口；FileID/storageKey/媒体版本是素材身份。记录node标题、组标题/成员、选中的多图imageId、用途、来源类型；原文件名及生成记录仅使用已有事实，不从URL猜测本地路径，不展示凭据或签名URL。
- 支持来源状态未知/原件缺失，定位原节点失效时仍保留历史描述。
- 当前来源详情点击展开：缩略图、标题、组关系、用途、稳定文件标识、已有原文件名、已有生成模型/记录。正文不堆磁盘路径。

## 提交快照

- 请求前从实际采用输入创建深拷贝快照：最终提示词、引用顺序/标签、稳定媒体身份/版本、来源描述、模型及非敏感参数。
- 请求使用此快照确定的媒体集合；禁止提交后又从变化中的节点重算历史。
- 使用现有Works generation-history inputSnapshot机制保存；未绑定Works的画布也需要独立持久生成记录，不能只保留最后一次节点metadata覆盖历史。
- 历史显示以快照为准，原节点改名/换图/删除不篡改历史。重试新建尝试并固定其输入。
- 来源展示针对image/text/video/audio生成路径一致，优先复用既有video snapshot、Works归档、FileID。不加迁移兜底、不改消息存储格式。

## UI

正文使用既有chip及悬停预览；下方实际引用清单显示编号+缩略图+标题+来源/用途，点击展开详情并可定位节点。明确标题“本次提交”与“当前草稿”。未引用/不支持列表单独显示原因。

## 验收标准

组和多图来源准确；排序后标签与请求一致；同一图片多用途不丢关系；缺文件/不支持明确阻止或提示；换图改名后历史不变；重试/失败/取消保留尝试；刷新从本地记录恢复；URL/参数不含凭据。无收费生成，无测试/build除非用户明确要求，运行项登记pending-test。

执行顺序：先完成upstream引用/AutoDL移植，再主模型复核统一输入链，之后接来源数据/UI/历史快照。本文件定义完整范围，尚未完成实现。
