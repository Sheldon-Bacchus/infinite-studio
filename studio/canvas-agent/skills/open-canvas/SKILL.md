# 打开、连接和操作画布

本插件来自当前仓库的应用主线，并通过唯一运行时 `npx -y @tigerowo/canvas-agent@latest` 获取并运行 npm 上的 Agent；画布操作使用本插件 MCP 提供的现有工具。命令不依赖仓库或插件缓存目录，不要混用其他分支的 Agent 包。

- 已连接且目标画布已确认时，直接操作，跳过下方连接流程；首次连接、目标改变或连接失效时再确认目标。
- 直接调用当前对话提供的画布 MCP 工具，不编写临时脚本另建 MCP 客户端。工具缺失时定位插件加载状态和启动错误，不以脚本调用成功代替插件工具加载成功。
- 目标选择使用 `list_connected_canvases` 和 `select_canvas`：按用户提供的真实画布 ID 锁定；同一画布有多个连接时必须指定列表中的 `clientId`。锁定后先用 `get_canvas_summary` 核对返回的项目 ID，再执行任何写入。绝不根据浏览器当前标签或“唯一连接”猜测用户目标。
- 连接或工具 schema 更新后，MCP 会通知 Codex 刷新工具列表。工具列表仍缺失时，核对运行时包版本和 MCP 进程状态，不把源码声明或浏览器可访问当成工具已加载。
- 普通创建节点使用已知工具定义和必要参数，不重复读取工具清单；操作需要已有节点、内容、来源或当前选择时才按需查询画布。
- 工具已返回成功、节点 ID 和节点数据时，以返回结果为准，不再查询整张画布验证；报错、结果不明确或用户要求复查时再追加检查。

## 建立连接

npx 自动获取包及依赖，无需用户进入插件缓存安装依赖。缺少 Node.js 22+、npm/npx 或下载失败时说明实际错误并停止，不改用开发机路径。

Windows 启动权限：执行第 3 步后台服务或第 5 步浏览器打开命令时，使用用户的正常桌面账户，连接配置也应属于同一桌面用户。现有权限不足时，先通过执行工具实际发起桌面执行权限申请；工具支持 `sandbox_permissions` 时设置为 `require_escalated` 并填写 `justification`，获批后自动继续，覆盖当前命令的已有授权直接复用，不额外聊天确认。仅申请配置目录写入权限不能替代桌面执行权限，不在沙箱账户中强行启动。

会话禁止申请权限、用户拒绝或自动审批拒绝时，停止对应启动，明确说明被拒绝的操作和原因；不修改权限策略、不换工具绕过拒绝，也不默认转成让用户在 PowerShell 手动执行。用户主动选择手动方式时再提供命令。

1. 优先使用用户已经给出的画布 URL 和已观察到的原画布标签，不重复索取地址。实际画布路由是 `/canvas/[id]`。不同浏览器或配置文件可能没有同一份本地项目；连接已有画布时保留原浏览器环境，不先在内置浏览器打开裸链接。只有用户要求新建时，才在目标站点 `/canvas` 列表通过现有“新建”操作进入画布，不能拼造画布 ID。无法确定站点时再询问实际地址。
2. 执行 `npx -y @tigerowo/canvas-agent@latest config` 读取 `{url, token, origins}`，并请求其 `GET /config` 判断服务是否已启动。config 不改本机连接配置。HTTP `/config` 只提供 `{url, hasToken}`，不包含 Token；首次尚无本机配置时进入启动步骤。
3. 服务未运行时，在可见终端运行 `npx -y @tigerowo/canvas-agent@latest` 并保持进程存活；不要隐藏终端窗口。不要安装或发布额外全局包。启动失败或端口属于其他服务时读取错误并停止，不反复启动或结束未知进程。已有服务正常时不要重复启动。
4. 读取启动输出的 `Local URL`、`Connect token`，或再次执行 `npx -y @tigerowo/canvas-agent@latest config`。Token 保存在当前用户的 `~/.infinite-canvas/codex-agent.json`，无需用户创建 `.env`、生成 Token 或录入网站来源。不要在回复、文档或额外日志中复制 Token 或包含它的完整连接链接。
5. 原画布标签可控时，用标准 `URL` 和 `URLSearchParams` 保留原链接及其他 fragment 参数，设置 `agentUrl`、`agentToken`，在该标签打开连接链接。原浏览器不可控时，执行 `npx -y @tigerowo/canvas-agent@latest open "<原画布URL>" <浏览器> [浏览器参数...]`，入口会自动带入凭据并打开浏览器，无需读取或输出完整连接链接。浏览器取 `chrome`、`edge`、`firefox`、`brave`；只有已确认原画布使用系统默认浏览器时才用 `default`。使用已确认的原配置文件参数；无法确定原浏览器或配置时只询问缺失的信息，不猜测、不切换内置浏览器。Token 仅写入 fragment，不放普通 query。
6. 打开命令成功不代表已连接。先调用 `list_connected_canvases`，再用 `select_canvas` 按用户给出的画布 ID 锁定；同一画布多个标签时提供指定 `clientId`。随后 `get_canvas_summary` 必须返回相同项目 ID，才能继续用户任务。无需控制系统浏览器标签。网页的本地网络权限提示由用户允许。失败时定位服务、网页连接或原浏览器配置的问题，不转成手填 Token 教程，不用其他画布替代目标。

## 本地素材进入镜头组

- 只有当前 MCP 工具清单真实包含 `list_local_assets`、`import_assets_to_canvas`、`create_config_draft` 或 `bind_config_media` 时才使用这些能力；源码或 Skill 文档里存在名称不代表运行时已加载。
- 用 `list_local_assets` 取得画布本地素材库的真实 `assetId`。导入只使用用户确认的素材 ID，不猜文件路径、不读取任意本地文件，也不调用 DramaClaw 目录导入。
- `import_assets_to_canvas` 是普通素材导入动作，不依赖固定镜头编号或预建分组；素材导入后再按用户确认的结构组织，不自动堆连线。
- 配置节点的 `composerContent` 必须包含真实 `@[node:<nodeId>]` 芯片。按配置显示的引用顺序绑定本镜图片和音频，并保留 H3 提示词正文；文字标签和来源连线不代表素材已绑定。
- 用户把整个组拖到视频配置节点时，`bind_config_group` 会把该组内的提示词、图片、视频和音频节点一次性加入配置；只在用户明确要求整组绑定或已完成该手动拖放时调用。它保留当前组内提示词、按节点在画布上的位置排序素材、保存画布草稿，不提交生成；发现组外引用、空组或非视频配置时报告工具返回的原因，不猜测或替用户改组。
- AutoDL 按当前工作流详情返回的 `input_rules` 接收组内引用：图片、视频和音频各占工作流已有槽位。若组内数量超过实际可用槽位，生成前明确提示超限；插件不得改写用户 AutoDL 账户中的远端工作流 JSON。
- 素材导入、配置草稿和芯片绑定只保存画布草稿，不提交图片、视频或音频生成任务。每步按 MCP 回执确认节点 ID、镜头组、媒体引用和保存结果；工具不可用、权限不足或回执不明确时停止写入并报告原始错误。

浏览器连接需要与 Agent 在同一台电脑，npm 包下载后仍在本机运行。Codex 未登录时执行 `npx -y @openai/codex@0.156.1 login`，让用户完成登录；不要读取或复制账号凭证。只执行用户请求所需的启动、连接和画布操作。
