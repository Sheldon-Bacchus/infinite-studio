# 本地开发

如果你需要改代码，建议前后端分开启动

## 1. 准备环境变量

```bash
cp .env.example .env
```

默认配置下：

- 后端只监听本机 `127.0.0.1:8081`
- 前端端口是 `3000`
- SQLite 数据库是 `data/infinite-canvas.db`

## 2. 启动后端

在仓库根目录执行：

```bash
go run .
```

后端会读取根目录 `.env`，并监听：

```text
http://127.0.0.1:8081
```

## 3. 启动前端

在 `web` 目录执行：

```bash
bun run dev
```

前端默认访问：

```text
http://localhost:3000
```

开发代理默认转发到 `http://127.0.0.1:8081`。如果你的后端端口不同，启动前设置 `API_BASE_URL`

画布项目统一保存到 SQLite 的 `local-workspace` 数据域；项目媒体默认保存到 `data/files`，不再把浏览器 IndexedDB 作为画布真源。Edge、内嵌浏览器和其他本机页面都通过同一个 Next.js 代理访问该后端。

虾料项目、原稿、分集、剧本、镜头，以及虾塘角色/身份、场景/变体、道具、声线和关联媒体记录也保存在同一 `local-workspace`：文本和领域字段进入 SQLite 的本地素材记录，上传的媒体文件单独写入本机文件存储。前端通过 `/api/local/assets` 读取、`/api/local/assets/sync` 保存；“保存项目并进入虾镜”会等待接口返回并核对项目、原稿和分集记录后再跳转。浏览器 IndexedDB/localForage 仍用于旧素材迁移、缓存和部分生成历史，不是这些创作记录的权威副本。

登录后的账号素材同步是可选副本：只有账号配置 `syncCapabilities.userData === true` 时，素材变更才会额外同步到账号数据服务。它不替代本地工作区；未开启该能力时，本机 SQLite 和文件目录仍是当前创作数据的持久化位置。虾塘页面的部分新增/编辑提示发生在异步本地同步完成前，遇到“已保存”提示仍应以刷新后重新读到记录为验收依据。

当前虾料实现仍有不符合产品边界的路径：`local-studio-pages.tsx` 中“生成分集结构”调用用户配置的文本模型并把完整原文放进请求；创建处理器还要求至少一个分集，因此只有原稿时无法保存。虾镜脚本页也保留生成、逐行生成、AI 改写和模型设置调用，必须一并移除页面模型执行路径。`local-studio-repository.ts` 保存后若 ID 缺失或 payload 不一致，会统一显示“本地保存响应缺少项目或原始剧本”，这条提示本身不能证明后端没有写入。配套规格要求原稿可独立保存、无标题时不伪造第一集、页面不发模型请求、客户端先固定 IDs/commitId 并在异常后回读 canonical 数据。现有数据库批量 Asset 写入有事务，初始批次按原子成功/失败核验；“部分成功”只用于多阶段画布投影，不得误报为原稿批次结果。本段记录当前实现和目标差异，不表示修复已经完成。

## 一键启动

桌面“无限画布”快捷方式指向 `studio/launch-infinite-canvas.cmd`。默认使用生产模式：源码变化时先编译全部前端路由，构建成功后才启动网页；产物未变化且服务健康时直接复用。这样打开虾塘、虾镜等路由时不会再触发 Next.js 开发模式的逐页首次编译。后端、前端和 Canvas Agent 分别监听本机回环地址上的 `8081`、`43861`、`3210`；新启动的服务会保留独立可见终端。Agent 使用 `studio/canvas-agent/index.mjs`，不通过 npm 临时下载另一个版本。

需要热更新时显式运行开发模式：

```powershell
.\launch-infinite-canvas.cmd -Development
```

开发模式使用 `next dev --webpack`，路由会在首次请求时编译。默认生产模式通过 `next start` 从 `web/` 工作区启动，避免 Windows 下 standalone 目录中 pnpm 链接引发的 `EPERM`。从 Codex 内侧栏打开画布、不另开系统浏览器时，可给启动器加 `-NoOpen`。

启动器会检查 `43861 -> 8081` 的本地 API 桥接。若 43861 上是本仓库遗留的旧前端，会替换该旧进程；若是其他服务，则会停止并提示，避免误杀。

## 常见场景

- 改画布、页面和交互：主要看 `web/`
- 改接口、业务逻辑和数据库：主要看仓库根目录下的 Go 代码
- 改文档站内容：主要看 `docs/content/docs/`
