# DramaClaw 画布排版 Skill

## 排版目标

排版服务于读者理解和后续生成，不是按创建时间随机铺网格。优先保持三类空间：

1. 剧本与镜头文本：左侧，按集数和 beat 顺序从上到下。
2. 分镜、关键帧、视频和音频：位于对应镜头附近，按“文字 → 配置 → 画面/视频/音频”的阅读方向展开。
3. 角色、场景、道具和构图参考：单独放在参考区，按对象分组，不和某个镜头的生产链混在一起。

## DramaClaw 导入布局

- 每个 episode 使用一个顶层 group；子节点的 `groupId` 必须指向真实 group。
- 目录导入采用两列 beat 网格：每个 beat 的文字节点在左，生成配置在右；画面在文字下方，视频和音频继续向右展开。
- 最终资产包采用三段式布局：文本列在 x=0；最终分镜图从 x=520 开始按 4 列排列；批准参考图从 x=1960 开始纵向排列。这个布局数字只属于导入投影器，Agent 不得在普通 `arrange_nodes` 调用中手写坐标。
- 导入投影的 viewport 可使用约 0.6 的缩放让三段区域同时可见，但不能覆盖用户已经保存的 viewport，除非用户明确要求重置视图。

## 连线与分组

- 连线表示真实生产依赖：剧本到镜头、镜头到对应配置、参考到实际使用它的媒体。
- 分组表示共同语义：角色参考集、场景参考集、章节或 beat；分组不改变生成参数。
- 不把全部节点连接到总剧本；不按生成顺序把平级参考串成链；不创建嵌套 group；一个节点只能属于一个 group。
- 导入关系默认是 evidence-only，不代表导入后可以直接生成。

## 调用规则

- 用户只说“导入”时先完成导入，不额外整理已有节点。
- 用户明确说“整理、排列、排版、对齐”时，才调用 `arrange_nodes`；优先传真实目标 nodeIds，未指定范围时整理当前顶层节点。
- 用户只要求分组时只调用 `create_group`，不调用 `arrange_nodes`。
- 排版前后不改变节点正文、提示词、模型、媒体地址、任务状态和连线语义。
- 排版后使用工具真实返回的节点位置/状态（若工具返回）描述结果；当前通用整理器不能声称完成了精确的 DramaClaw 三段式布局，除非导入投影器已返回该布局。

## 检查清单

- 文本能否按 episode / beat 顺序阅读？
- 每个媒体是否紧邻它的直接来源？
- 参考是否和镜头生产链分离？
- 是否存在重复导入、孤立连线、错误 groupId 或把 loading 媒体当成成品的情况？
- 是否保留了 sourceSystem、sourceProjectId、sourceEpisode、sourceRevision 和 sourceEntityId？
